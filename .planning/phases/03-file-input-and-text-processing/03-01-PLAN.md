     - `"txt"` => `Txt`
     - `"md" | "markdown"` => `Markdown`
     - `"pdf"` => `Pdf` (also validate first 4 bytes are `b"%PDF"`, warn via eprintln if not but still return `Pdf`)

     - `Pdf` => `pdf::extract(path)`
     - `Unknown` => per D-02: print warning `"Warning: Unrecognized file type '{}', attempting as plain text..."` with the extension, then call `txt::extract(path)`. If txt::extract fails (binary/non-UTF-8), return error `"File contains binary or non-UTF-8 content and cannot be processed as text."`
   - Declare `mod txt; mod markdown; mod pdf;`

4. Create `src/extract/txt.rs` with:
   - `pub fn extract(path: &Path) -> anyhow::Result<String>` that calls `std::fs::read_to_string(path).context("Failed to read text file")`
   - Per D-10: read as-is, UTF-8 assumed, no processing.

5. Create `src/extract/markdown.rs` with:
   - `use pulldown_cmark::{Event, Parser, Tag, TagEnd, Options};`
   - `pub fn extract(path: &Path) -> anyhow::Result<String>`:
     - Read file with `std::fs::read_to_string`
     - Create `Parser::new_ext(&source, Options::empty())`
     - Track `in_code_block: bool` state
     - Event mapping per D-05, D-06, D-07 and research recommendations:
       - `Event::Start(Tag::Heading { .. })` => ensure `\n\n` before if output not empty
       - `Event::End(TagEnd::Heading(_))` => append `\n\n` (pause marker per D-05)
       - `Event::Start(Tag::CodeBlock(_))` => set `in_code_block = true`, append `"\n\nA code block appears here. See the original document for details.\n\n"` (per D-06)
       - `Event::End(TagEnd::CodeBlock)` => set `in_code_block = false`
       - `Event::Start(Tag::Image { .. })` => append `"\n\nAn image appears here. See the original document for details.\n\n"` (per D-07)
       - `Event::Text(text)` when `!in_code_block` => append text
       - `Event::Code(text)` => append text (inline code spoken naturally)
       - `Event::SoftBreak | Event::HardBreak` => append `" "`
       - `Event::End(TagEnd::Paragraph)` => append `"\n\n"`
       - `Event::Rule` => append `"\n\n"` (section break)
       - `Event::Start(Tag::Table(_))` / table-related => skip (per research: complex layout, poor TTS)
       - Everything else => skip
     - Return `Ok(output)`

6. Create `src/extract/pdf.rs` with:
   - `use pdf_extract::extract_text as pdf_extract_text;`
   - `pub fn extract(path: &Path) -> anyhow::Result<String>`:
     - Read first 4 bytes, check `starts_with(b"%PDF")`. If not, bail with `"File does not appear to be a valid PDF (missing %PDF header)"` (per D-01 content validation).
     - Call `pdf_extract_text(path).context("Failed to extract text from PDF")?`
     - Quality heuristic per D-08:
       - Count alphanumeric chars: `text.chars().filter(|c| c.is_alphanumeric()).count()`
       - Count garbage chars: `text.chars().filter(|c| *c == '\u{FFFD}').count()`
       - If `alpha_count < 50`: `eprintln!("Warning: Very little text extracted from PDF. The file may be image-based (scanned).")`
       - If `garbage_ratio > 0.05` (garbage_count as f64 / text.len().max(1) as f64): `eprintln!("Warning: Extracted text contains unusual characters. Results may be imperfect.")`
     - Image-page detection heuristic per D-09: pdf-extract does NOT expose image metadata, so inline image detection is not possible. Instead, use a per-page proxy heuristic:
       - Split extracted text by form-feed characters (`'\x0C'`) to approximate page boundaries (pdf-extract inserts form-feeds between pages).
       - For each page segment, count alphanumeric characters. If a page has fewer than 20 alphanumeric characters but is not completely empty (i.e., it has some whitespace or control chars), it is likely an image-heavy or diagram page.
       - For each such detected page, insert a placeholder into the text at that page boundary: `"\n\nThis page appears to contain images or diagrams that cannot be extracted as text. See the original document for details.\n\n"`
       - After processing all pages, emit a single summary warning if any image-pages were detected: `eprintln!("Warning: {} page(s) appear to contain mainly images/diagrams. Spoken placeholders were inserted (per D-09). Note: pdf-extract cannot detect inline images within text-heavy pages.")` This documents the limitation transparently to the user.
       - If form-feed splitting yields only one segment (no page boundaries detected), skip this heuristic entirely -- single-segment PDFs cannot be analyzed per-page.
     - Return `Ok(text)` (with placeholders inserted where applicable)

1. `pub fn chunk_by_paragraph(text: &str) -> Vec<String>`:
   - Split on `"\n\n"` (double newline, per D-03)
   - Trim each chunk
   - Filter empty chunks (per research pitfall 3)
   - For each remaining chunk, if `chunk.len() > 3000` (per research recommendation for very long paragraphs, addressing pitfall 2), call `split_long_paragraph(chunk)` and extend results
   - Return final Vec<String>

2. `fn split_long_paragraph(text: &str) -> Vec<String>`:
   - Split at sentence boundaries: find positions where `. ` is followed by an uppercase letter or newline
   - Accumulate sentences into sub-chunks, starting a new sub-chunk when accumulated length exceeds 3000 chars
   - If no sentence boundaries found (one giant run-on), split at 3000 char boundaries at the nearest space
   - Return Vec<String> of sub-chunks, each trimmed and non-empty

The constant `3000` (max chars per chunk) can be a `const MAX_CHUNK_CHARS: usize = 3000;` at module level.
